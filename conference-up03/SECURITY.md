# Безопасность приложения

Пароли хешируются scrypt со случайной солью. В базе хранится хеш случайного идентификатора сессии; cookie HttpOnly и SameSite=Strict. Изменяющие запросы требуют CSRF. После пяти неудачных входов с одного IP — блокировка на пять минут. Вход проверяет Origin, разрешающий CORS отсутствует. Host ограничен, CSP/X-Frame-Options/nosniff установлены, debug отключён.

SQL параметризован, ввод проверяется Pydantic. CSV нейтрализует начало формул. Импорт только для admin, до 10 МБ, с подтверждением REPLACE; ссылки, email, идентификаторы и вместимость проверяются до транзакции. Backup использует SQLite Backup API. Restore создаёт новый файл и очищает сессии.

## Модель данных и прав

Это общий реестр оргкомитета, а не личный кабинет участника. Участники не имеют логинов. Проверка «чужих данных» — запрет viewer читать именные записи и запрет operator экспортировать/заменять общие данные. Контроль применяется в API, а не только скрытием кнопок.

## Ограничения

Демо-пароли публичны, режим предназначен для loopback. Для публикации нужны HTTPS, новая БД, приватный пароль и проверка окружения. Управление аккаунтами и сброс пароля через интерфейс не входят в релиз. Блокировка по IP может затронуть сотрудников за одним NAT.

Локальная SQLite и локальные backup не обеспечивают отказоустойчивость крупного мероприятия. Проверка advisories отражает известные уязвимости на дату запуска, а не доказательство полной безопасности.

В Issue прикладывайте версии и воспроизводимые шаги на вымышленных данных. Не включайте .env, действующие cookies, пароли и реальные экспорты участников.
