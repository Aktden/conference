# Порядок сдачи

Комплект содержит переработанный исходный проект, документы по всем шести этапам и реальные результаты локальных проверок. Исходная база сохранена отдельно от папки для публичного Git.

## Перед показом

1. Укажите ФИО и группу в начале восьми Word-документов. Эти сведения не были предоставлены и не выдуманы.
2. При необходимости переименуйте папки submission/Этап1…Этап6 по шаблону УП03_ЭтапN_Фамилия_Имя_Группа. Содержимое не меняется.
3. Выполните scripts/setup.bat, scripts/run.bat; далее DEMO_GUIDE.md.
4. Подтвердите Docker и BAT в целевой среде. Скриншоты этих действий добавьте в evidence/screenshots. Существующие PNG относятся к реальному браузерному запуску Linux.

## Git с сохранением истории

В корне общего комплекта приложен conference-history.bundle. Он содержит исходный коммит УП.02, ветку support/conference-up03 и коммиты доработок. После распаковки выполните вне папки исходников:

```sh
git clone conference-history.bundle conference-git
cd conference-git
git switch support/conference-up03
git branch main origin/main
git remote remove origin
git remote add origin https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
git push -u origin support/conference-up03
git push origin main
```

Если локальная main уже существует, пропустите команду её создания. Не создавайте её от текущей ветки: используйте origin/main из bundle, чтобы сохранить исходную базу для PR.

Создайте на GitHub пустой репозиторий без README. Скопируйте его реальный адрес в repo_link.txt, выполните commit и push в support/conference-up03. Затем создайте Issue по docs/GITHUB_ISSUE.md и Pull Request из support/conference-up03 в main по docs/GITHUB_PR.md. В описании PR замените указатель на фактический Issue. Дождитесь Actions. При ошибке изучите лог, исправьте и повторите push. После успешных проверок можно merge и создать тег v3.0.0.

Альтернатива — загрузить исходники через веб-интерфейс GitHub; это не переносит историю Git и само по себе не закрывает требование ветки/PR. Не публикуйте отдельную копию исходных данных, .env, рабочую БД, backups и .venv.

## Что нужно подтвердить на GitHub

- Созданный Issue с воспроизведением и ожидаемым результатом.
- Ветка и коммит исправления.
- Успешный workflow Conference CI.
- Pull Request и оформленное слияние.
- Тег или GitHub Release с архивом.

В комплекте нет нарисованных скриншотов GitHub, Docker или Windows. Их нужно получить после реального выполнения. Локальные логи и скриншоты уже включены; карта соответствия — REQUIREMENTS_MATRIX.md.
