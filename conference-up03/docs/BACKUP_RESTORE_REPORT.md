3. Выполнено backup_database в новый файл; integrity_check и foreign_key_check успешны.
4. Выполнено restore_database в другой новый файл. Сессии и login_attempts очищены.
5. Проверены количества записей и целостность восстановленного файла.

## Повторение на Windows

```bat
scripts\backup.bat
scripts\restore.bat backups\ИМЯ_КОПИИ.db data\restored.db
```

На Linux: `.venv/bin/python scripts/manage.py backup`, затем `.venv/bin/python scripts/manage.py restore backups/ИМЯ_КОПИИ.db --target data/restored.db --confirm RESTORE`.

Restore отказывается перезаписывать существующий файл. После проверки остановите сервер, измените DATABASE_PATH на новый файл и запустите приложение; войдите повторно. Оригинальную базу сохраняйте до приёмки. Полный backup содержит персональные данные и хеши паролей, поэтому не помещается в Git.
