# Демонстрация преподавателю

Сценарий занимает 7–10 минут; используйте вымышленные демо-данные.

1. Покажите структуру и шесть отчётов submission. Объясните связь с УП.02: сохранены участники, секции, посещения и SQLite.
2. Выполните scripts\run.bat после установки. Войдите admin / DemoAdmin!2026.
3. Объясните показатели обзора: один участник может иметь несколько регистраций на секции.
4. Создайте Проверочный Иван, check@example.com, слушатель. Повторите email и покажите обработанный конфликт.
5. Создайте секцию вместимостью 1, запишите участника, отметьте приход. Попытка записать второго отклоняется.
6. Откройте печать бейджа. Отмена печати не меняет статус; отдельно нажмите «Выдан».
7. Экспортируйте JSON, откройте аудит. Войдите viewer / DemoViewer!2026: доступны сводки без именных данных.
8. Выполните scripts\check.bat. Покажите тест одновременной регистрации и объясните исправление SQLite.
9. Выполните backup, затем `scripts\restore.bat backups\ИМЯ_КОПИИ.db data\restored-demo.db`. Покажите количества записей.
10. Покажите коммиты, CHANGELOG и релиз. После публикации — Issue, PR и реальный успешный workflow.

## Ответы на вопросы

Почему SQLite: не нужен отдельный сервер, для локального учебного стенда достаточно. Проверка вместимости и запись объединены BEGIN IMMEDIATE.

Зачем lifespan: таблицы создаются при ASGI-запуске. В старой версии init_db выполнялся только при прямом запуске main.py.

Где защита: роли проверяет сервер, пароль — scrypt-хеш, сессия — HttpOnly cookie, изменения требуют CSRF, import валидируется до транзакции.

Что осталось развивать: управление учётными записями, удалённые резервные копии, мониторинг диска и нагрузочное тестирование крупного мероприятия.
